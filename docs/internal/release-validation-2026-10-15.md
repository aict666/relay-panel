# 计费第二批与发布候选验收记录

日期：2026-10-15。候选版本：Panel **1.4.0** / Node **1.3.11**，配置协议 v11；原始工作区基线 `v1.3.22`。修改尚未提交、推送、打标签、发布或部署生产，因此以下是**本地候选代码/产物验收**，不是线上发布结果。

## 补齐的业务行为

- 持久化订阅与 UTC 周期：月付提前续购只购买未来周期，当前用量不清零。按成交快照激活，不重新扣款，不用新商品覆盖已付权益。
- 扣款、兑换、余额调整、订单、幂等记录与账本同事务；流水写入失败整笔回滚。余额只使用整数分，历史迁移只登记期初余额。
- 免费注册套餐开通试用与线路，收费注册只保存意向；首次付费开通真实周期。保守修复无任何使用/付款/线路证据的旧收费注册账户。
- 预付权益存在时拒绝直接换套餐、清除、改期；保护已付快照中的线路。封禁/暂停取消自动扣款授权，周期切换不解除停用状态，不恢复手动暂停规则。
- 自助账户展示状态、当前周期、未来预付数与流水；管理员可查指定用户流水；订单展示成交类型与 UTC 权益区间。
- 节点流量 outbox 私有原子持久化、fsync、凭据/URL 隔离及文件锁；已封装批次重启重放。损坏状态拒绝启动，不能清空文件假装恢复。
- 升级前准备镜像、检查 Compose，再停旧容器并备份实际旧库；备份失败尝试恢复原容器，不用新配置重建。备份工具及还原演练覆盖 SQLite / 外部 PostgreSQL。
- 收尾核对补齐公告日期旁项：新写入补零 UTC 格式，升级修复可解析的旧日期；无法解析的手工数据保留并告警，不擅自删除公告。真实 HTTP 与双库旧库恢复用例覆盖新旧日期。

前端 build 仍有既有大型 antd/charts chunk 警告，它不是类型/构建错误，不能据此声称已完成包体优化。

浏览器以构建后的真实前端连接隔离 Panel：验证购买确认、实扣一次、预付数递增、当前 500 B 用量与 1000 B 额度不变；订单新旧价格/周期分别保存，管理员流水可见。管理页面保存暂停状态时未修改余额或将小额度误写为不限。窄窗口下账本在表格内横向滚动，不撑宽页面。

失败恢复容器用例曾因旧端口健康检查超时而失败；独立复现证实 Docker 对同一容器 stop/start 会重新分配测试的随机宿主端口。测试修正为只重新查询绑定、不执行额外启动/重建，之后两种镜像均通过。生产 Compose 的固定映射不受此测试端口现象影响；未以“进程启动成功”代替真实健康验收。

## 发布边界与运营前置条件

结论：已识别的计费/权益和本轮发布安全阻断项已修复，当前代码可进入**授权后的正式发布流水线**。这不等于生产已经上线，也不等于可以跳过下面三项实际门槛：远程原生 AMD64/ARM64 产物与 Registry 验收、生产数据库副本迁移/恢复、真实环境小流量灰度与核账。

本地设备是 ARM64，**没有把 x86_64 原生构建、GitHub 权限/Registry 推送、多架构清单发布声称为已实跑**。这些已作为两条 release workflow 的强制步骤，只有在获准提交并触发发布后才能得到远程验收结果。业务数据库副本迁移与真实生产灰度也必须由运营发布时完成。

双架构范围是 Panel 镜像和 Node 静态二进制。Node 发行 Docker 工作流保持既有的 AMD64 单架构；本地 ARM64 Node 源码镜像测试不等于发行流水线提供 ARM64 节点镜像，ARM64 部署应选静态二进制或自行构建。

当前收费闭环仅为兑换码与余额；没有第三方支付/退款回调/财务对账平台。流量按接收批次的当前周期入账，不提供逐字节跨周期结算或硬退出零丢字节保证。具体备份、兼容、发布、回滚步骤见 [发布运行手册](../RELEASE-1.4.0.md)。
