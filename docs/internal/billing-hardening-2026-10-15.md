## 交付范围

保留当前分支的多跳、UOT、共享隧道与协议阻断，不整包合并上游、不换镜像。本批解决计量、扣款重试和权益约束的基础问题，**不是完整订阅系统或支付平台交付**。

| 项目 | 本批行为 |
|---|---|
| 流量上报 | 节点保留同一批次号和同一份字节快照，超时、丢 ACK、500 时原样重试；401 也不换号，因为认证失败不能证明前次未入账；面板将批次去重记录和用量原子提交 |
| 旧入口与规则删除 | 已成功入账的重试先查批次，不因规则已删除/迁移而再次拒绝；沿用本地退休入口归属校验 |
| 长连接 | TCP、TLS、WebSocket 传输中持续记账；TCP/TLS 和 WS 上传按成功写入字节计量，包括写入一部分后出错/取消；Linux splice 在每次 pipe→socket 成功时计量 |
| 多跳 | 仍由收费入口计一次，下游 TCP 隧道不重复收费；协议探测回放前缀单独计一次 |
| 管理员余额 | 普通编辑不再带回未修改的余额；修改余额必须带 `expected_balance`，在写锁内按整数分比较；冲突返回 409，整次编辑回滚 |
| 购买幂等 | 自助购买、管理员代购必须带 `request_id` 和确认的价格/商品版本/当前套餐；同一用户、同一交易号、同一意图仅扣一次；复用交易号更改意图返回 409 |
| 浏览器断网 | 本标签页的待确认交易及商品快照保存在 sessionStorage；网络错误/500 后重试原交易，刷新或重新进入页面也保留；不会悄悄生成新交易号 |
| 套餐降级 | 按规则 ID 保留最早的可运行规则，超额配置标记自动暂停，不删除；恢复入口检查运行规则上限；购买升级只恢复系统暂停的规则，不恢复手动暂停的规则 |
| 不限额度 | `traffic=0` 始终表示不限，不再当作叠加数值；当前不限转有限时使用新商品有限额度 |
| 非月付 reset 商品 | 重置时使用商品新额度并清零，而非“旧额度叠加后又返还历史消耗”；普通流量包续购继续增加额度、保留已用 |
| 充值 | SQLite 在读取兑换码和余额前取得写锁，避免不同有效码并发兑换时的快照升级错误 |
| 兑换日期 | 新建时规范化 UTC 日期；存量非补零日期在兑换时按真实时间解析；到期瞬间及无法解析的过期时间均拒绝兑换，不批量改写历史行 |
| 自动续费 | 开启时绑定套餐 ID、金额、计费版本；封禁和暂停均取消扣款授权，恢复账户不会自动重新授权；扫描和最终扣款事务均检查账户状态，暂停中购买也不能重新开启自动扣款 |

### 有意保留的边界

- 新购产生的“相同用户、相同商品、不同交易号”仍是两个独立购买意图，不以时间窗口猜测用户是否误操作。
- 规则创建仍沿用当前保存数量约束；本批新增的是降级后存量启用数量与恢复检查，不删除超额配置。
- WS 下载按成功发送的应用帧负载计量，不把封装/握手字节计入商品流量。TCP/TLS/splice 按成功写入目标的数据计量，不保证对端应用已消费。
- 用量仍受上报周期、配置传播延迟影响，不是逐字节实时硬限额。
- 节点计数器和待上报批次仍在内存；进程硬退出会丢失尚未成功上报的字节。随机批次号避免重启碰撞，但**本批未实现磁盘 outbox**。

## 数据库与兼容性

- SQLite 追加迁移 60～62：`traffic_batches`、`purchase_requests`，以及历史超额运行规则的安全暂停。
- PostgreSQL 追加修订 45～47，同样语义；版本上限提升至 47。
- 成功购买意图与扣款、订单、权益处于同一事务。交易号不随删除用户而级联删除；这只是幂等记录，**不能替代完整余额变动账本**。
- 流量批次按设备组隔离。节点收到 ACK 后，在下一批确认上一批；已确认记录保留七天后清理。未确认记录不按年龄删除，防止离线恢复后重复计量。
- 数据库升级会暂停历史超额规则，但不改历史余额、用量、订单、商品价格或套餐有效期；未自动计算或返还历史错账。
- 新面板继续接受不含批次号的旧节点上报，但旧节点没有丢 ACK 去重保障。
- **升级顺序必须是面板及配套前端 → 节点。** 新节点连旧面板，旧面板会忽略批次号，不能获得去重保证。
- 旧购买客户端需补交易号及确认字段；旧余额编辑客户端需补原余额。缺字段会被拒绝，不默默执行不安全扣款/覆盖。
- 开启自动续费需补 `expected_plan_id`；关闭不需要这些确认字段。
- 未修改配置协议版本 v11、下载源、发布版本或许可证；没有提交、推送或部署。
